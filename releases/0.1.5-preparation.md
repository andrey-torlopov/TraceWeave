# 0.1.5 — local source preparation

Prepared on 2026-10-11. This version has not been published. The current published selection remains `stable.json` / 0.1.4; there is no registry manifest or Docker Hub image claim for 0.1.5.

## Included changes

- Arbitrary attachments and PDF downloads, independent repeated attachments, preserved original bytes and safe download-only handling for generic content.
- Authenticated native image/audio/video and download requests work with account fencing enabled. Sessions, investigation ownership and mutation guards remain required.
- Separate raw-data and readable-report exports. The readable ZIP contains one `report.md` and `Attachments/`, with human-readable document attributes and relations from an immutable capture.
- OpenAPI 1.3.0 and additive migrations 8–9. Earlier migration bytes are unchanged.

The exact backend/frontend commits are pinned in [source-lock.json](source-lock.json). Local `v0.1.5` tags identify the prepared revisions. No tag or branch has been pushed as part of this preparation.

## Local source build

After obtaining the private component repositories beside the delivery checkout, check out their pinned revisions and run from the delivery root:

```sh
./traceweave.sh build-source \
  --release-id 0.1.5 \
  --backend-version 0.1.5 \
  --frontend-version 0.1.5 \
  --delivery-version 0.1.5 \
  --backend-path ../TraceWeaveBackend \
  --frontend-path ../TraceWeaveFrontend
```

All three checkouts must be committed and clean. The operator creates an ignored `releases/0.1.5.local.json` using actual local image IDs. Runtime and OCI versions are supplied by the version arguments above; the frontend npm package version is not the application release version. This Docker build was not run during preparation.

## Upgrade and recovery

A future update from schema 7 applies migrations 8 and 9 after a verified offline database/originals backup. The migrations widen allowed file/export kinds without rewriting originals or existing domain records. Old prepared client commands keep their existing format and reviewed contract hashes.

After schema 9, a schema-7 binary cannot open the database. Image-only rollback to 0.1.4 is therefore refused; use a compatible fixing release or restore the verified pre-update backup into new volumes. Recovery duration depends on the real data size and was not measured here. No running installation or user database was migrated during preparation.

# 0.2.2 — read-first document cards

Document cards open in reading mode from the graph, list and search. A dedicated layout shows the full title, type, assessment, formatted Markdown, attachments and a semantic attribute list. Desktop uses a note column with an attribute sidebar; narrow screens stack the content. Both themes and the saved project width preference remain supported.

The ✍️ toggle beside Close exposes the existing editor. Its accessible name is stable, `aria-pressed` reflects its state, and a green frame plus the visible mode label distinguish editing. Header controls remain available while scrolling. Closing and reopening starts in reading mode; the mode is intentionally not persisted.

Reading and editing share one DocumentStore/draft. Switching does not discard unsaved text; pending/error/recovery states remain visible and can be reviewed in the editor. Reading hides upload, retry/cancel, detach, delete and field controls while retaining existing media previews, download authorization and size limits. Archived projects cannot enable editing. Attribute formatting preserves unknown, empty, zero, false, partial date precision and explicit UTC datetimes. Markdown keeps the existing safe renderer and blocks automatic external image requests.

API 1.4.0, database schema 11, dependencies and lock files remain unchanged. Same-schema updates retain installed gateway/database/tools; older schemas receive the existing coordinated tools upgrade. Image-only rollback to 0.2.1 requires equal migration histories; older schemas require a verified backup restore into new volumes. Publication does not update existing installations.

Native source, publication, anonymous clean-host installation and all published update baselines must pass before stable promotion. Real Safari, Firefox and full P0/performance acceptance are outside these scoped checks. Final evidence is added after completed gates.

# 0.1.6 — release notes

Release 0.1.6 adds arbitrary attachments and a readable report, with coordinated backup-tool updates for existing installations. See the [release manifest](0.1.6.json), [source lock](source-lock.json) and user guides in [English](../docs/en/releases.md) or [Russian](../docs/ru/releases.md).

The immutable [0.1.5 candidate](0.1.5-preparation.md) was not promoted because update acceptance found a restore defect. Version 0.1.6 carries the same features and corrects that defect without a new contract or migration.

## Included changes

- Arbitrary attachments and PDF downloads, independent repeated attachments, preserved original bytes and download-only handling for generic content.
- Authenticated native image/audio/video and download requests work with account fencing enabled. Sessions, investigation ownership and mutation guards remain required.
- Separate raw-data and readable-report exports. The readable ZIP contains one `report.md` and `Attachments/`, with document attributes and relations from an immutable capture.
- OpenAPI 1.3.0 and additive migrations 8–9. Earlier migration bytes are unchanged; reviewed client contracts retain exact replay of earlier prepared commands.
- Restore writes complete errors for interrupted upload/export/import jobs. The backend also reads historical error records without `fields` as an empty field list, while malformed field values remain invalid. Restored export jobs report `export_interrupted` and can be replaced with a fresh ZIP.

## Upgrade and recovery

Update the delivery checkout, then run `./bootstrap.sh` from the existing installation directory with the same runtime. After confirmation, the script creates and verifies an offline database/originals backup before applying migrations and replacing application images. Installations on 0.1.0/0.1.1 apply migrations 7–9; those on 0.1.3/0.1.4 apply migrations 8–9. No manual SQL or migration selection is required.

Bootstrap selects one of four manifests by retained infrastructure: [0.1.0](0.1.6-update-infra-0.1.0.json), [0.1.1](0.1.6-update-infra-0.1.1.json), [0.1.3](0.1.6-update-infra-0.1.3.json) or [0.1.4](0.1.6-update-infra-0.1.4.json). PostgreSQL and gateway remain selected; backend/frontend and backup tools update together. The manifest records the explicit `toolsUpgrade` and separate `source.tools` provenance.

Earlier backup tools rejected arbitrary-file storage keys under `files/`. The 0.1.6 tools image includes those originals while preserving strict path and checksum validation. Retaining an older tools image with the new application would leave these backups unsupported.

After schema 9, a schema-7 binary cannot open the database. Image-only rollback to 0.1.3/0.1.4 or an earlier schema is refused; use a compatible fixing release or restore the verified pre-update backup into new volumes. Restore preserves the previous volumes, creates a safety backup of the current state and revokes existing sessions.

The safety backup can later return the installation to its newer state. Restore verifies each backup with that backup’s target tools version before changing data. The exact tools image must be known from the installed/previous release or a valid local release manifest. Keep the updated delivery scripts and reviewed `releases/` catalog; if the required tools are unknown, obtain the matching manifest from the official release. Backup metadata alone is not permission to execute an arbitrary tools image.

Export ZIPs are transient and are not copied into backups. Restore invalidates earlier export jobs; create fresh raw-data or readable-report ZIPs from the restored documents. Data created after a selected backup is retained in the old volumes and safety backup, without automatic merging.

## Local source build

After obtaining the private component repositories beside the delivery checkout, check out their pinned revisions and run from the delivery root:

```sh
./traceweave.sh build-source \
  --release-id 0.1.6 \
  --backend-version 0.1.6 \
  --frontend-version 0.1.6 \
  --delivery-version 0.1.6 \
  --backend-path ../TraceWeaveBackend \
  --frontend-path ../TraceWeaveFrontend
```

All three checkouts must be committed and clean. The operator creates an ignored `releases/0.1.6.local.json` using actual local image IDs. Runtime and OCI versions are supplied by the version arguments above; the frontend npm package version is not the application release version.

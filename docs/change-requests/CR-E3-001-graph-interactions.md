# CR-E3-001 — запрошенный пакет графа

Дата: 2026-10-09. Статус: принято в объёме прямого запроса владельца на компактные узлы, drag, связи и double-click; до ответа на дополнительный вопрос используется буквальное правило исходного запроса для длинного заголовка. Ответственный: A.

## Основание и граница

Текущий E2 UI открывает полноценную карточку сразу после создания и явно отключает drag/connect. Владелец запросил рабочие компактные узлы и связи по референсу `Source/Reference/Снимок экрана — 2026-10-08 в 16.10.14.png`.

Этот прямой запрос задаёт следующий целевой пакет E3 до полной приёмки E2. Это исключение из последовательности §24 только для перечисленных взаимодействий, не признание E2 или E3 завершёнными. Q-04 и его негативный тест остаются открыты; требования надёжности не снимаются. Группы, материалы, undo/redo и последующие этапы сюда не входят.

## Поведение

- Новый обычный узел остаётся компактным; форма открывается по двойному клику. Карточка и инспектор остаются независимыми, общий draft store сохраняется.
- Скруглённая рамка целиком окрашена цветом типа; локальная иконка типа обеспечивает дополнительное различение. Полный заголовок в данных не сокращается. До ответа на дополнительное уточнение действует исходное правило: если заголовок длиннее 40 символов либо не помещается — иконка типа; полный текст в tooltip/accessible name, outline и карточке. Это рабочая трактовка, не полученный ответ на дополнительный вопрос.
- Однократно перевести browser UI state v1→v2: старые expanded от прежнего auto-open свернуть, остальные UI-настройки и черновики сохранить. Намеренно открытые карточки v2 опять восстанавливаются после reload. Изменений документов/БД это не вызывает.
- Перетаскивание обычных узлов сохраняет абсолютные координаты командой layout.move. Открытую карточку можно двигать за заголовок, редактирование текста не тянет узел.
- Drag от соединительной точки либо действие «Связать с…» открывает подтверждение свойств. До подтверждения связи нет в БД; отмена не оставляет запись.
- Связь — одна кубическая кривая Безье. Ответ владельца: «Выбирать сторону, одна кривая». Алгоритм оценивает четыре стороны каждого конца и препятствия, выбирает наименее перекрытый разумный вариант. Полный обход всех препятствий не обещается. Стороны вычисляются из геометрии, не сохраняются в Relation/SQL; новых полей или миграции не требуется.

## Проверка

Drag → подтверждение сервера → reload/restart; connect → confirm → reload/restart; duplicate/self/cross-investigation/invalid coordinates/atomic rollback/replay/stale revision; double-click, редактирование без drag, длинный Unicode title и обе темы. Эти проверки принимают пакет, но не полный E3.

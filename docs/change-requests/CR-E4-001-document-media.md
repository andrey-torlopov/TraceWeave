# CR-E4-001 — медиафайлы в документе и каталоги оригиналов

2026-10-09. Принято в объёме прямого запроса владельца. Координатор A.

## Запрос и противоречие

Владелец запросил загрузку файлов для audio/video/image, три подпапки и просмотр в карточке. ТЗ §11/12.8/13.4/14 уже предусматривает Asset/Blob/NodeAttachment, ticket, потоковый PUT, атомарную регистрацию и авторизованную выдачу. Однако исходный CHECK blobs.storage_key допускает только `<prefix>/<key>` и запрещает категорию в пути. Менять immutable SQL0001 нельзя.

Варианты: оставить единый плоский каталог; добавить категории с совместимой миграцией; разделить RG_DATA_DIR на независимые хранилища. Выбрана совместимая миграция: оригиналы в `RG_DATA_DIR/blobs/images`, `blobs/audio`, `blobs/video`; серверные имена, старые ключи продолжают приниматься. Текстовые материалы сохраняют legacy layout. Старые файлы не перемещаются и не удаляются автоматически.

## Решение

Координатор назначает migration0004: расширение storage_key CHECK с сохранением старой формы, проверенные MIME/mediaKind и размеры изображения в Blob. Nullable поля для старых Blob не фабрикуют проверенный формат; существующий Asset сохраняется. UploadTicket получает проверенные MIME/kind/SHA через Blob. Размеры позволяют вычислять previewAllowed до браузерного декодирования; лимит preview32MP из ТЗ §23.4 синхронизируется с capabilities. 0001–0003 неизменны. Следующий свободный номер для будущего Q-04 —0005.

Доменная регистрация/привязка только через `asset.register` и `attachment.attach`; `attachment.detach` отсоединяет без удаления оригинала. Физический storage key не отдаётся обычному API. Реализуются существующие upload-ticket/PUT/GET/cancel, getAsset и GET/HEAD content с одиночным Range. Неподдерживаемые контейнеры/поддельные сигнатуры/размеры отклоняются, байты потоковые; пароль/DSN/содержимое не логируются. Внешних загрузок и конвертации нет.

Уточнение совместимости: migration0004 разрешает однократное заполнение ранее неизвестных verified-полей legacy Blob после реальной проверки SHA и формата. Уже заполненные метаданные, ключ, размер и хеш неизменяемы. Регистрировать просроченный ticket нельзя (404); незавершённый/cancelled ticket — 409 job_not_ready; повтор уже зарегистрированного ticket — 409 upload_already_registered с assetId.

UI: раздел материалов в общем редакторе/инспекторе, picker с фильтром типа документа, статус каждого upload и повтор, native image/audio/video. Тип узла не меняет доменную допустимость вложений и не удаляет их при смене типа. Codecs браузера могут ограничивать воспроизведение: явное сообщение и download-original; autoplay выключен, закрытие останавливает playback. CSP получает только media-src 'self'. Лимиты из capabilities, оригинал512MiB.

Это целевой пакет E4 до полного gate E2/E3, явно разрешённый новым запросом. Полная библиотека материалов, drag&drop на фон графа, text preview, отчёты, importer и конвертация вне пакета. Тестирование внутреннего текстового формата допустимо для совместимости, но UI текстовых вложений этим пакетом не обещается. E2 Q-04 и полнота остальных этапов сохраняют прежний статус.

## Проверки

Fresh/upgrade0004 и legacy keys; upload/bytes/hash/MIME/category/path; spoof/truncated/overlimit/interrupted/repeat/cancel/TTL/cross-owner/cross-investigation; регистрация/rollback/однократный ticket/revision/exact replay; attachment/shared original/detach; GET/HEAD/206/416/multirange/seek/authorization; no autoplay/stop-on-close/codec fallback/image limit; reload и настоящий backend/PostgreSQL restart; backup c вложенными категориями. Только синтетические данные. Команды и реальные результаты фиксируются в Artifacts/media-attachments.md; полный E4 gate отдельно.

# CR-E0-002 — текущая приёмка на macOS, плагины отложены

**Статус:** принято прямым ответом владельца 2026-10-08. Приоритет выше ТЗ 1.1, согласно §0.

## Основание

Q-01: «Разрешаю сборки и установку необходимых утилит».
Q-02: «Текущая реализация пусть будет на macos когда будем заворачивать в докер-контейнер может быть придется доработать какой-то функционал».
Q-03: «С плагинами пока ничего не делаем. Можно сделать фейковый плагин, в который мы передаем путь к папке, он смотрит вней файлы md и склеивает их в один файл result.md».

## Принятое изменение

- Сборки, тесты и установка необходимых инструментов разрешены. Разрешение не означает публикацию, изменение пользовательских БД или удаление пользовательских материалов.
- Текущая целевая платформа — используемая macOS arm64; фактически macOS 26.6.2/Swift 6.2.4. Linux x86_64/arm64 и Docker откладываются до отдельной контейнеризации. MacOS build/test и настоящая PostgreSQL остаются обязательными.
- Обязательные части §18, plugin schemas/fixtures и AC-59/60 отложены из текущей приёмки. CR-E0-001 закрыт отложенным объёмом, не восстановлением отсутствующих файлов. Никто не утверждает, что исходный комплект проверен.
- Допустим самостоятельный синтетический пример объединения Markdown в result.md. Он не запускается сервером, не устанавливается как plugin, не получает доступ к БД/учётной записи и не выдаётся за готовую plugin-систему.
- Gates E0/AC-65/AC-68/§27 применяются к текущему macOS-объёму: Linux и plugin-протокол не блокируют; остальные функциональные требования сохраняются.

## Последствия и проверка

Доменная модель, PostgreSQL, API, координаты, серверное сохранение, безопасность, отчёты и переносимость не меняются. Нет миграции пользовательских данных. Документы, preflight и приёмочная матрица должны ссылаться на это изменение. Сборки и integration-проверки выполнять на macOS, Linux отмечать отложенным без объявления поддержки. Утилиту Markdown проверить на порядок, UTF-8, отсутствие самовключения result.md и безопасный отказ без частичной перезаписи.

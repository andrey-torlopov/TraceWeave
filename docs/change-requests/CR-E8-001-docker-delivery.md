# CR-E8-001 — реализация Docker-поставки

**Статус:** принято прямым запросом владельца 2026-10-10: идти по Artifacts/docker-deployment-plan.md и реализовать контейнеры; SRC/TraceWeave создан владельцем.

## Конфликт и решение

CR-E0-002 откладывал Docker/Linux до отдельной контейнеризации. Текущий запрос активирует этот пакет. D-02/§21–22 предполагают раздачу статики Vapor, D-08/§16.2 — одного владельца и пароль12; принятый план требует отдельных backend/frontend/db/gateway, аккаунтов/email/SMTP и минимум3 Unicode scalar values. План имеет приоритет для этого пакета; полные E2–E8/P0 не объявляются принятыми.

## Данные и API

Три самостоятельных Git-репозитория; PostgreSQL18 сохраняется. Миграции0001–0005 неизменяемы, номер0006 назначен аккаунтам. UUID/хеш старого владельца сохраняются; привязка email только оператором, никакого захвата аккаунта первым посетителем. API расширяется согласованно. DB TLS verify-full сохраняется; локальный HTTP допускается только явным контейнерным режимом с loopback-публикацией и доверенным выделенным gateway.

## Проверка

Критерии плана §10: чистый bootstrap, безопасный повтор, данные после пересоздания, отдельные образы, maintenance HTML/JSON503, совместимые версии, негативные обновления, backup/restore и аккаунты/изоляция. Проверки только на синтетических установках. Публикация GHCR/GitHub и внешний deploy отдельно; SMTP/домен/публичность образов записываются в Artifacts/docker-owner-actions.md. Без удаления данных/volumes.

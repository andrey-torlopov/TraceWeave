# CR-E2-001 — единое измерение лимита extensions

**Статус:** ожидает решения владельца, 2026-10-09.

## Воспроизводимое расхождение

ТЗ §12.4 требует namespaced-метаданные до 16 KiB, но не определяет текстовое представление для подсчёта. OpenAPI Extensions.x-maxJsonUtf8Bytes и Swift WIP проверяют компактный JSON; SQL baseline0001 rg_valid_extensions проверяет octet_length(v::text), где PostgreSQL добавляет пробелы после разделителей.

Read-only эксперимент на PostgreSQL тестового кластера: объект с ключом app.test и строкой из 16369 ASCII-символов.

```text
compact UTF-8 = 16384 bytes; PostgreSQL jsonb::text UTF-8 = 16385 bytes; limit = 16384 bytes
```

То есть одна и та же граница проходит прикладную проверку, но нарушает SQL CHECK. Перевод такого случая в 422 предотвращает техническую 503, но сам по себе не согласует допустимый объём.

## Варианты

1. **Рекомендуется:** считать 16384 байта UTF-8 компактной сериализации JSON без необязательных пробелов, единообразно в API и БД. Зафиксировать правила сериализации чисел/экранирования, синхронизировать валидаторы и тесты; добавить следующую миграцию вместо изменения принятой 0001.
2. Считать размер PostgreSQL jsonb::text. Сохранить SQL-проверку, явно закрепить эту форму в API/документации и прикладной проверке. Это делает доступный объём зависимым от текстового представления PostgreSQL.

## Влияние

Стек и модель данных сохраняются; значения метаданных не должны теряться или обрезаться. Меняется только единое правило проверки границы. Вариант 1 требует новой версии SQL-функции в новой миграции, вариант 2 — уточнения публичного контракта. Пользовательская БД в этой сессии не изменяется.

## Проверка

Положительные/отрицательные случаи на точной границе и на один байт сверх неё, ASCII/кириллица/emoji, вложенные объекты/массивы, экранирование, числа. При отказе ожидается 422 с JSON Pointer и полный rollback. На валидной границе — commit и идентичное содержимое после GET/restart.

## Граница остановки

До ответа не менять SQL-функцию/миграции и правило подсчёта extensions. Остальные согласованные части E2 можно реализовывать и проверять. E2 не объявлять принятым до согласования.

# CR-E2-003 — универсальная карточка и поиск по вхождению

2026-10-09. Принято в пределах прямого запроса владельца в текущем чате. Координатор A.

## Основание и конфликт

Владелец запросил убрать подзаголовок и теги, создавать заметку без выбора типа, выбирать тип в деталях и использовать тип только для визуального оформления. Также запросил поиск по вхождению строки в название, содержимое и ключи/значения атрибутов с переключателем регистра. Это уточняет ТЗ §7–8 и заменяет FTS/AND-семантику §14.7 для текущего поиска карточек; CR-E4-001 ранее привязывал начальный фильтр загрузки к типу документа.

## Решение

- Удалить поля subtitle/tags из пользовательского редактора. Для совместимости сохраняются поля API/SQL и существующие значения; destructive migration не проводится. Новые документы используют null/[] по существующим defaults. В новый поиск эти поля не включаются.
- Форма создания запрашивает заголовок и создаёт системный note. Тип выбирается только в деталях. Обычные типы используют одинаковые поля и загрузку всех поддерживаемых медиа. Смена типа не меняет содержимое, атрибуты, вложения или пользовательский фильтр файлов. Системная группа сохраняет свой отдельный доменный смысл.
- Сервер ищет все активные документы текущего исследования, включая не открывавшиеся в браузере. Совпадение — буквальная подстрока отдельно в title, bodyMarkdown, ключе или отображаемом значении любого атрибута. Запрос не разбивается на слова/операторы; SQL wildcards не исполняются. Unicode NFC; по умолчанию caseSensitive=false. Пустой запрос в UI возвращает обычный список документов.
- GET/POST существующего /api/v1/investigations/{id}/search получают необязательный caseSensitive=false. Текущий пакет реализует только objectKinds=[node]; неподдерживаемые виды/фильтры отношений отклоняются явно. Полный E6-поиск связей/материалов не объявляется реализованным.
- Выдача одна на документ, содержит поле и безопасный текстовый фрагмент; 50 на страницу, максимум 200, UUID-сортировка, cursor с revision и digest всех фильтров. Изменение ревизии требует cursor_stale и обновления выдачи. Чтение без изменения ревизии, авторизация владельца, исключение корзины. Поиск читает исходные данные PostgreSQL без обрезания Markdown и без нового индекса/миграции.
- Поиск доступен в панели документов на desktop и в мобильном drawer; результат открывает документ и позволяет перейти к нему на графе. Ошибки, загрузка, пустая выдача, отмена устаревшего запроса и обновление после сохранения обрабатываются явно.

## Проверки

Создание note без селектора; отсутствие старых полей; изменение типа при сохранении текста/атрибутов/медиа; поиск title/body/key/value, кириллица/латиница/регистр, пунктуация и literal %/_/backslash, typed/null attributes, длинный текст и конец 5 MiB документа, пагинация/устаревший cursor, изоляция исследования/владельца, исключение корзины и отсутствие мутаций. Реальный backend + синтетическая PostgreSQL + браузер. macOS; Linux и настоящий Safari отдельно не подтверждаются.

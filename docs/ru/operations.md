# Эксплуатация и восстановление

*[English](../en/operations.md)*

Выполняйте команды из каталога установки с прежним `TW_RUNTIME_DIR`. Сохраняйте runtime и Docker volumes: не удаляйте их для обхода ошибки.

## Ежедневные команды

| Команда | Результат |
| --- | --- |
| `./traceweave.sh status` | Адрес, выпуск, фаза установки и состояние сервисов |
| `./traceweave.sh start` | Запуск установленного приложения |
| `./traceweave.sh stop` | Штатная остановка с сохранением данных |
| `./traceweave.sh restart` | Перезапуск под обслуживанием |
| `./traceweave.sh logs backend db` | Последние строки журналов выбранных сервисов |
| `./traceweave.sh resume` | Проверяемое продолжение поддерживаемой прерванной операции |

Во время обслуживания приложение временно недоступно. Дождитесь завершения; сохраняйте введённые браузерные черновики. Для изменения SMTP используйте `./traceweave.sh configure-mail` с параметрами провайдера по [серверному руководству](server-deployment.md). Пароли вводятся скрыто. Не публикуйте частные журналы/настройки.

## Приватный backup

```sh
./traceweave.sh backup
```

Приложение переходит в обслуживание, согласованно копирует базу и оригиналы, проверяет копию и возобновляет работу. Завершённая копия находится в указанной командой папке `runtime/backups/`. Убедитесь, что операция завершена, и перенесите **полный каталог** на отдельное защищённое хранилище.

Backup содержит данные всех аккаунтов и приватные записи аутентификации. Сам TraceWeave не шифрует копию; используйте шифрование и ограничьте доступ. Отдельно сохраните private `runtime/secrets/`, `installation.json`, `release.json` и файлы нужного выпуска. Не помещайте их в Git, webroot или общую папку экспорта. [Таблица хранения и границы защиты](data-and-security.md).

## Restore в новые хранилища

Полный внешний backup сначала верните под его исходным именем в приватный `runtime/backups/` этой установки, не перезаписывая другую копию и не используя symlink. Имя вводится без пути:

```sh
printf 'Имя завершённого backup в runtime/backups/: '
IFS= read -r TW_BACKUP_NAME
./traceweave.sh restore --backup "$TW_BACKUP_NAME"
./traceweave.sh status
```

Restore требует подтверждения, делает страховочную копию текущего состояния и создаёт новые database/files volumes. Прежние volumes сохраняются. Нужно место для обеих копий и новых хранилищ. После успешного восстановления войдите заново. Более поздние записи остаются в прежних volumes/страховочном backup; они не объединяются с выбранным старым снимком автоматически.

## Если операция прервалась

Сначала прочитайте `status` и журналы. Исправьте причину и оставьте обслуживание включённым. Bootstrap обнаруживает незавершённую операцию и не начинает поверх неё новую установку или обновление. Для поддерживаемых фаз update/backup/restart воспользуйтесь `resume`; для прерванного restore автоматический resume запрещён. `./traceweave.sh restore-revert` возвращает сохранённые прежние volumes/выпуск и сохраняет кандидат восстановления.

Обновление и откат выполняйте по [руководству релизов](releases.md). Не запускайте вторую конкурирующую операцию и не заменяйте recovery удалением volumes или raw `docker compose down`. Если CLI отказывает, сохраните состояние и диагностические сообщения для разбора.

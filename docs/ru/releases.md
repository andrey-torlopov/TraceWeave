# Релизы и обновления

*[English](../en/releases.md)*

Поставка **0.1.3** использует публичные образы amd64/arm64. Проверенный [manifest](../../releases/0.1.3.json), [выбор по умолчанию](../../releases/stable.json) и [образ tools](../../releases/tools-image.txt) доступны в репозитории и [GitHub Release v0.1.3](https://github.com/andrey-torlopov/TraceWeave/releases/tag/v0.1.3).

## Новая установка

Используйте новый каталог:

```sh
git clone --branch v0.1.3 --depth 1 https://github.com/andrey-torlopov/TraceWeave.git TraceWeave-0.1.3
cd TraceWeave-0.1.3
curl -fL --output releases/0.1.3.json https://github.com/andrey-torlopov/TraceWeave/releases/download/v0.1.3/0.1.3.json
curl -fL --output releases/tools-image.txt https://github.com/andrey-torlopov/TraceWeave/releases/download/v0.1.3/tools-image.txt
./bootstrap.sh --release releases/0.1.3.json
```

Образы закреплены по digest. Приватные исходники и вход в реестр не нужны. Исторический тег может содержать прежние статусы документации; актуальные гайды находятся в main.

## Существующая установка

Из прежнего каталога установки с тем же runtime:

```sh
git pull --ff-only
./bootstrap.sh
./traceweave.sh status
```

Скрипт покажет установленную и доступную версии и предложит обновление. После согласия он скачает образы, включит обслуживание, создаст и проверит резервную копию базы и оригиналов, автоматически применит миграцию 7 и проверит готовность. Выбирать миграцию или запускать SQL вручную не требуется. После завершения перезагрузите вкладку браузера.

Для установок 0.1.0 и 0.1.1 скрипт сам выбирает подходящий проверенный manifest: [с сохранённой инфраструктурой 0.1.0](../../releases/0.1.3-update.json) или [для полной установки 0.1.1](../../releases/0.1.3-update-from-0.1.1.json). Backend/frontend обновляются до 0.1.3; база, gateway, tools, runtime и хранилище остаются прежними. Сохраняются сессии, оригиналы и ассеты ранее открытых вкладок. Ранее подготовленные запросы можно повторить без изменения исходных байтов.

Отказ, конец ввода или неинтерактивный запуск сохраняют прежний выпуск. Для заранее согласованного автоматизированного обновления используйте `./bootstrap.sh --yes`. Скрипт не понижает версию; при прерванной операции он укажет на `resume`/восстановление. `git pull` сам контейнеры не меняет. Публикация в Docker Hub также не обновляет уже работающие установки.

## Возврат после миграции

У 0.1.3 новая схема базы. Обычный `./traceweave.sh rollback` отклонит возврат старых образов на эту схему. Используйте совместимый исправляющий выпуск или [восстановление резервной копии](operations.md) в новые volumes. Восстановление возвращает данные на момент копии и сохраняет прежние volumes и дополнительную копию текущего состояния. Прежние сессии отзываются; после restore нужно войти заново.

В 0.1.3 разрешены несколько связей между теми же узлами, четыре направления и фиксированные концы в диалоге. Удаление узла вместе со всеми входящими/исходящими связями остаётся доступно.

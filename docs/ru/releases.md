# Релизы и обновления

*[English](../en/releases.md)*

Поставка **0.1.4** использует публичные образы amd64/arm64. Проверенный [manifest](../../releases/0.1.4.json), [выбор по умолчанию](../../releases/stable.json) и [образ tools](../../releases/tools-image.txt) доступны в репозитории и [GitHub Release v0.1.4](https://github.com/andrey-torlopov/TraceWeave/releases/tag/v0.1.4).

## Новая установка

Используйте новый каталог:

```sh
git clone --branch v0.1.4 --depth 1 https://github.com/andrey-torlopov/TraceWeave.git TraceWeave-0.1.4
cd TraceWeave-0.1.4
curl -fL --output releases/0.1.4.json https://github.com/andrey-torlopov/TraceWeave/releases/download/v0.1.4/0.1.4.json
curl -fL --output releases/tools-image.txt https://github.com/andrey-torlopov/TraceWeave/releases/download/v0.1.4/tools-image.txt
./bootstrap.sh --release releases/0.1.4.json
```

Образы закреплены по digest. Приватные исходники и вход в реестр не нужны. Исторический тег может содержать прежние статусы документации; актуальные гайды находятся в main.

## Существующая установка

Из прежнего каталога установки с тем же runtime:

```sh
git pull --ff-only
./bootstrap.sh
./traceweave.sh status
```

Скрипт покажет установленную и доступную версии и предложит обновление. После согласия он скачает образы, включит обслуживание, создаст и проверит резервную копию базы и оригиналов и проверит готовность. При переходе с 0.1.3 миграций нет; при переходе с 0.1.0/0.1.1 автоматически применяется существующая миграция 7. Выбирать миграцию или запускать SQL вручную не требуется. После завершения перезагрузите вкладку браузера.

Для установок 0.1.0, 0.1.1 и 0.1.3 скрипт сам выбирает проверенный совместимый manifest по сохранённой инфраструктуре: [0.1.0](../../releases/0.1.4-update-infra-0.1.0.json), [0.1.1](../../releases/0.1.4-update-infra-0.1.1.json) или [0.1.3](../../releases/0.1.4-update-infra-0.1.3.json). Backend/frontend обновляются до 0.1.4; база, gateway, tools, runtime и хранилище остаются прежними. Сохраняются сессии, оригиналы и ассеты ранее открытых вкладок. Ранее подготовленные запросы можно повторить без изменения исходных байтов.

Отказ, конец ввода или неинтерактивный запуск сохраняют прежний выпуск. Для заранее согласованного автоматизированного обновления используйте `./bootstrap.sh --yes`. Скрипт не понижает версию; при прерванной операции он укажет на `resume`/восстановление. `git pull` сам контейнеры не меняет. Публикация в Docker Hub также не обновляет уже работающие установки.

## Откат и восстановление

Между 0.1.3 и 0.1.4 схема базы не меняется; `./traceweave.sh rollback --yes` возвращает прежние образы и сохраняет данные. После перехода с 0.1.0/0.1.1 на схему 7 обычный image rollback отклоняется. Используйте совместимый исправляющий выпуск или [восстановление проверенной резервной копии](operations.md) в новые volumes. Восстановление возвращает данные на момент копии, сохраняет прежние volumes и дополнительную копию текущего состояния. Прежние сессии отзываются; после restore нужно войти заново.

В 0.1.4 добавлена [настройка порога детализации графа](features.md): кнопка с шестерёнкой, целый коэффициент 2–10, стандартное значение 3. Значение 5 превращает карточку в компактный узел на масштабе 20% и ниже. Несколько связей, четыре направления и удаление узла со всеми входящими/исходящими связями сохраняются.

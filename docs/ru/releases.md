# Релизы и обновления

*[English](../en/releases.md)*

Поставка **0.1.9** использует публичные образы amd64/arm64. [Manifest](../../releases/0.1.9.json), [выбор по умолчанию](../../releases/stable.json) и [образ tools](../../releases/tools-image.txt) доступны в репозитории и [GitHub Release v0.1.9](https://github.com/andrey-torlopov/TraceWeave/releases/tag/v0.1.9). Изменения и результаты проверок приведены в [описании выпуска](../../releases/0.1.9-preparation.md).

Опубликованные теги и образы 0.1.5 остаются неизменяемыми, но кандидат не продвинут: приёмка обновления обнаружила ошибку после restore. [Протокол кандидата](../../releases/0.1.5-preparation.md) содержит завершённые проверки и причину отказа. Используйте выпуск 0.1.9, включающий это исправление.

## Новая установка

Используйте новый каталог:

```sh
git clone --branch main --depth 1 https://github.com/andrey-torlopov/TraceWeave.git TraceWeave
cd TraceWeave
./bootstrap.sh --release releases/0.1.9.json
```

Образы закреплены по digest. Приватные исходники и вход в реестр не нужны. Исторический тег может содержать прежние статусы документации; актуальные гайды находятся в main.

## Существующая установка

Если checkout уже отслеживает `main`, выполняйте команды из его каталога с тем же runtime:

```sh
git pull --ff-only && ./bootstrap.sh
./traceweave.sh status
```

Если установка клонировалась из тега выпуска, checkout находится в detached HEAD и эта команда pull для него не работает. Начните в **исходном каталоге установки**; если использовали нестандартный runtime, предварительно задайте прежний `TW_RUNTIME_DIR`. Команды ниже проверят существующий runtime, покажут его абсолютный путь и создадут отдельный checkout, отслеживающий `main`:

```sh
TW_EXISTING_RUNTIME=${TW_RUNTIME_DIR:-$PWD/runtime}
if [ ! -L "$TW_EXISTING_RUNTIME" ] &&
   [ -f "$TW_EXISTING_RUNTIME/installation.json" ] &&
   TW_RUNTIME_DIR=$(CDPATH= cd -- "$TW_EXISTING_RUNTIME" && pwd -P); then
  export TW_RUNTIME_DIR
  printf 'Существующий runtime: %s\n' "$TW_RUNTIME_DIR"
  TW_DELIVERY_DIR=$(mktemp -d "$(dirname "$PWD")/TraceWeave-main.XXXXXX") &&
  git clone --branch main --depth 1 https://github.com/andrey-torlopov/TraceWeave.git "$TW_DELIVERY_DIR" &&
  printf '%s\n' "$TW_RUNTIME_DIR" > "$TW_DELIVERY_DIR/.git/traceweave-runtime-path" &&
  cd "$TW_DELIVERY_DIR" &&
  printf 'Каталог поставки: %s\n' "$PWD" &&
  ./bootstrap.sh &&
  ./traceweave.sh status
else
  printf 'Прежний installation.json не найден либо runtime является symlink. Проверьте исходный путь runtime.\n' >&2
fi
```

Сохраните исходный checkout, runtime и Docker volumes на прежних местах. Новый checkout хранит только путь runtime в своих локальных метаданных Git. В **каждом новом терминале** войдите в этот новый checkout и восстановите переменную до любой команды `bootstrap.sh` или `traceweave.sh`:

```sh
TW_RUNTIME_DIR=$(cat .git/traceweave-runtime-path) &&
test -f "$TW_RUNTIME_DIR/installation.json" &&
export TW_RUNTIME_DIR &&
./traceweave.sh status
```

Если проверка не прошла, найдите исходный runtime до продолжения. После успешной проверки для следующих обновлений используйте обычные команды `git pull --ff-only` и bootstrap выше. Этот абсолютный `TW_RUNTIME_DIR` нужен также для backup, restore и остальных команд CLI.

Скрипт покажет установленную и доступную версии и предложит обновление. После согласия он скачает образы, включит обслуживание, создаст и проверит резервную копию базы и оригиналов и проверит готовность. С 0.1.7 миграции не нужны: схема остаётся 10. Более ранние выпуски обновляют базу до схемы 10: при переходе с 0.1.0/0.1.1 применяются миграции 7–10, с 0.1.3/0.1.4 — миграции 8–10, с 0.1.6 — миграция 10. Прежняя история миграций и оригиналы файлов не переписываются. Выбирать миграцию или запускать SQL вручную не требуется. После завершения перезагрузите вкладку браузера.

Bootstrap выбирает точный manifest по установленным версиям tools и gateway. 21 вариант покрывает 40 опубликованных баз. Backend/frontend обновляются до 0.1.9. При переходе с 0.1.7/0.1.8 сохраняются прежние backup tools и схема 10; более ранние схемы обновляют tools вместе с миграцией. PostgreSQL, gateway, runtime и хранилище сохраняются. Сессии, оригиналы, ассеты открытых вкладок и точные подготовленные запросы остаются доступны. Подробности — в [заметках выпуска](../../releases/0.1.9-preparation.md).

Отказ, конец ввода или неинтерактивный запуск сохраняют прежний выпуск. Для заранее согласованного автоматизированного обновления используйте `./bootstrap.sh --yes`. Скрипт не понижает версию; при прерванной операции он укажет на `resume`/восстановление. `git pull` сам контейнеры не меняет. Публикация в Docker Hub также не обновляет уже работающие установки.

## Откат и восстановление

После обновления с 0.1.7/0.1.8 до 0.1.9 команда `./traceweave.sh rollback --yes` с прежним runtime возвращает записанные предыдущие образы приложений. Схема и оригиналы не меняются. После отката проверьте status, вход и документы. Это применимо, если прежней установкой была 0.1.7 или 0.1.8 с той же историей миграций.

После миграции на схему 10 откат только образов на 0.1.6 (схема 9) или более раннюю схему запрещён. Старый backend не может открыть обновлённую базу. Используйте совместимый исправляющий выпуск или [восстановление проверенной резервной копии](operations.md) в новые volumes. Восстановление возвращает данные на момент копии, сохраняет прежние volumes и дополнительную копию текущего состояния. Прежние сессии отзываются; после restore нужно войти заново. Более новая страховочная копия позволяет затем вернуть состояние перед восстановлением, используя tools, соответствующие этой копии. Сохраните проверенные manifests выпусков в `releases/`: образ tools должен быть известен из истории установки или этого локального каталога до запуска restore. Проверка доверия и обращение с временными экспортами описаны в [руководстве эксплуатации](operations.md).

В 0.1.9 добавлены независимый размер иконки и дробный порог перехода карточек в иконки. См. [настройки графа](features.md).

В 0.1.8 все вложения карточки показаны кнопками с типом и именем файла. Нажмите кнопку для просмотра одного изображения, аудио или видео; прочие файлы скачиваются для просмотра на компьютере. При переключении прежний плеер останавливается. Файлы можно добавить вместе или последовательно. Отсоединение сохраняет оригинал и остальные вложения.

В 0.1.7 добавлен тип **«Улика»** с лупой 🔍 в поле «Тип документа». Документы и оценки проверенности сохраняются; пользовательский тип с тем же кодом или именем не перезаписывается и не дублируется.

В 0.1.6 добавлены [произвольные файлы и скачивание PDF](attachments.md), а также выбор [сырых данных или единого читаемого отчёта](exports.md). Исправлены просмотр медиа и скачивание оригиналов в авторизованной сессии; backup/restore включает оригиналы произвольных файлов. Также исправлено чтение ошибок прерванных upload/export/import после restore, включая записи прежних tools: задание экспорта сообщает о недоступном ZIP вместо ошибки загрузки самого задания. Настройки детализации графа, несколько связей, четыре направления и удаление узла со всеми входящими/исходящими связями сохраняются.

## Зафиксированные проверки

Публикация и CI 0.1.9 с точными ревизиями компонентов прошли на native amd64/arm64. На собранном amd64-контейнере прошли 33 Chromium-сценария графа и 11 сценариев вложений. Анонимная установка проверена на обеих архитектурах; все 80 обновлений с 40 опубликованных баз прошли. Проверены данные и исходные байты файлов, экспорты, точный replay, откат при одинаковой схеме, отказ несовместимого отката и оба направления backup/restore. [Публикация](https://github.com/andrey-torlopov/TraceWeaveBackend/actions/runs/38163986227), [CI](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38163980831), [registry](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38166127828), [обновления](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38166133230). Машинные [протоколы](../../releases/verification/0.1.9/publication.json) приложены к выпуску. Настоящий Safari, Firefox и полная приёмка P0 отдельно не выполнялись.

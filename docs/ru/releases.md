# Релизы и обновления

*[English](../en/releases.md)*

Поставка **0.2.0** использует публичные образы amd64/arm64. [Manifest](../../releases/0.2.0.json), [выбор по умолчанию](../../releases/stable.json) и [образ tools](../../releases/tools-image.txt) доступны в репозитории и [GitHub Release v0.2.0](https://github.com/andrey-torlopov/TraceWeave/releases/tag/v0.2.0). Изменения и результаты проверок приведены в [описании выпуска](../../releases/0.2.0-preparation.md).

Опубликованные теги и образы 0.1.5 остаются неизменяемыми, но кандидат не продвинут: приёмка обновления обнаружила ошибку после restore. [Протокол кандидата](../../releases/0.1.5-preparation.md) содержит завершённые проверки и причину отказа. Используйте выпуск 0.2.0, включающий это исправление.

## Новая установка

Используйте новый каталог:

```sh
git clone --branch main --depth 1 https://github.com/andrey-torlopov/TraceWeave.git TraceWeave
cd TraceWeave
./bootstrap.sh --release releases/0.2.0.json
```

Образы закреплены по digest. Приватные исходники и вход в реестр не нужны. Исторический тег может содержать прежние статусы документации; актуальные гайды находятся в main.

## Существующая установка

Если checkout уже отслеживает `main`, выполняйте команды из его каталога с тем же runtime:

```sh
git pull --ff-only && ./bootstrap.sh
./traceweave.sh status
```

Если установка клонировалась из тега выпуска, checkout находится в detached HEAD и эта команда pull для него не работает. Начните в **исходном каталоге установки**; если использовали нестандартный runtime, предварительно задайте прежний `TW_RUNTIME_DIR`. Команды ниже проверят существующий runtime, покажут его абсолютный путь и создадут отдельный checkout, отслеживающий `main`:

```sh
TW_EXISTING_RUNTIME=${TW_RUNTIME_DIR:-$PWD/runtime}
if [ ! -L "$TW_EXISTING_RUNTIME" ] &&
   [ -f "$TW_EXISTING_RUNTIME/installation.json" ] &&
   TW_RUNTIME_DIR=$(CDPATH= cd -- "$TW_EXISTING_RUNTIME" && pwd -P); then
  export TW_RUNTIME_DIR
  printf 'Существующий runtime: %s\n' "$TW_RUNTIME_DIR"
  TW_DELIVERY_DIR=$(mktemp -d "$(dirname "$PWD")/TraceWeave-main.XXXXXX") &&
  git clone --branch main --depth 1 https://github.com/andrey-torlopov/TraceWeave.git "$TW_DELIVERY_DIR" &&
  printf '%s\n' "$TW_RUNTIME_DIR" > "$TW_DELIVERY_DIR/.git/traceweave-runtime-path" &&
  cd "$TW_DELIVERY_DIR" &&
  printf 'Каталог поставки: %s\n' "$PWD" &&
  ./bootstrap.sh &&
  ./traceweave.sh status
else
  printf 'Прежний installation.json не найден либо runtime является symlink. Проверьте исходный путь runtime.\n' >&2
fi
```

Сохраните исходный checkout, runtime и Docker volumes на прежних местах. Новый checkout хранит только путь runtime в своих локальных метаданных Git. В **каждом новом терминале** войдите в этот новый checkout и восстановите переменную до любой команды `bootstrap.sh` или `traceweave.sh`:

```sh
TW_RUNTIME_DIR=$(cat .git/traceweave-runtime-path) &&
test -f "$TW_RUNTIME_DIR/installation.json" &&
export TW_RUNTIME_DIR &&
./traceweave.sh status
```

Если проверка не прошла, найдите исходный runtime до продолжения. После успешной проверки для следующих обновлений используйте обычные команды `git pull --ff-only` и bootstrap выше. Этот абсолютный `TW_RUNTIME_DIR` нужен также для backup, restore и остальных команд CLI.

Скрипт покажет установленную и доступную версии и предложит обновление. После согласия он скачает образы, включит обслуживание, создаст и проверит резервную копию базы и оригиналов и применит недостающие миграции до схемы 11. При переходе с 0.1.7–0.1.9 добавляется миграция 11; более ранние выпуски последовательно получают остальные недостающие миграции. Прежняя история миграций и оригиналы файлов не переписываются. Выбирать миграцию или запускать SQL вручную не требуется. После завершения перезагрузите вкладку браузера.

Bootstrap выбирает точный manifest по установленным версиям tools и gateway. Backend/frontend обновляются до 0.2.0, backup tools обновляются согласованно со схемой 11. PostgreSQL, gateway, runtime и хранилище сохраняются. Сессии, оригиналы, ассеты открытых вкладок и точные подготовленные запросы остаются доступны. Подробности — в [заметках выпуска](../../releases/0.2.0-preparation.md).

Отказ, конец ввода или неинтерактивный запуск сохраняют прежний выпуск. Для заранее согласованного автоматизированного обновления используйте `./bootstrap.sh --yes`. Скрипт не понижает версию; при прерванной операции он укажет на `resume`/восстановление. `git pull` сам контейнеры не меняет. Публикация в Docker Hub также не обновляет уже работающие установки.

## Откат и восстановление

Выпуск 0.2.0 переводит базу на схему 11. Команда `./traceweave.sh rollback --yes` откажет в возврате одних образов на 0.1.9 или более раннюю схему: старый backend не может открыть обновлённую базу.

Для возврата используйте совместимый исправляющий выпуск или [восстановление проверенной резервной копии](operations.md) в новые volumes. Восстановление возвращает данные на момент копии, сохраняет прежние volumes и дополнительную копию текущего состояния. Прежние сессии отзываются; после restore нужно войти заново. Более новая страховочная копия позволяет вернуть состояние перед восстановлением с соответствующими tools. Сохраните проверенные manifests в `releases/`: образ tools должен быть известен из истории установки или этого локального каталога. После восстановления проверьте status, вход, документы и скачивание оригиналов.

В 0.2.0 добавлены [полный ZIP-перенос проекта](exports.md), выбор типа документа сеткой иконок и персональный эмодзи выбранной карточки. Эмодзи не меняет тип или остальные карточки и сохраняется при переносе.

В 0.1.9 добавлены независимый размер иконки и дробный порог перехода карточек в иконки. См. [настройки графа](features.md).

В 0.1.8 все вложения карточки показаны кнопками с типом и именем файла. Нажмите кнопку для просмотра одного изображения, аудио или видео; прочие файлы скачиваются для просмотра на компьютере. При переключении прежний плеер останавливается. Файлы можно добавить вместе или последовательно. Отсоединение сохраняет оригинал и остальные вложения.

В 0.1.7 добавлен тип **«Улика»** с лупой 🔍 в поле «Тип документа». Документы и оценки проверенности сохраняются; пользовательский тип с тем же кодом или именем не перезаписывается и не дублируется.

В 0.1.6 добавлены [произвольные файлы и скачивание PDF](attachments.md), а также выбор [сырых данных или единого читаемого отчёта](exports.md). Исправлены просмотр медиа и скачивание оригиналов в авторизованной сессии; backup/restore включает оригиналы произвольных файлов. Также исправлено чтение ошибок прерванных upload/export/import после restore, включая записи прежних tools: задание экспорта сообщает о недоступном ZIP вместо ошибки загрузки самого задания. Настройки детализации графа, несколько связей, четыре направления и удаление узла со всеми входящими/исходящими связями сохраняются.

## Зафиксированные проверки

Публикация 0.2.0 и анонимная установка прошли на native Linux amd64/arm64. На собранном amd64-контейнере прошли 10 Chromium-сценариев редактора/переноса, 33 сценария графа и 11 сценариев вложений. Скачанные без авторизации image IDs совпали с протестированными images. Реальный ZIP64 writer/reader с архивом 4 831 854 009 байт проверен на macOS arm64; размеры и SHA всех оригиналов совпали. [Публикация](https://github.com/andrey-torlopov/TraceWeaveBackend/actions/runs/38752689149), [CI](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38751555640), [registry](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38756147808). Все 124 проверки обновления с 62 опубликованных вариантов установок прошли, включая автоматический backup, миграцию 11, точный replay и оба направления восстановления: [протокол](https://github.com/andrey-torlopov/TraceWeave/actions/runs/38757674385). Настоящий Safari, Firefox, нагрузочная матрица и полная приёмка P0 отдельно не выполнялись.

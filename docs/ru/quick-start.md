# Быстрый старт

*[English](../en/quick-start.md)*

Для запуска нужны Docker с Linux-контейнерами, Docker Compose, Git и интерактивный терминал. Исходники компонентов и учётная запись GitHub/Docker Hub не нужны. Образы выпуска 0.1.6 публичны для amd64 и arm64.

Из каталога, где будет храниться новая установка:

```sh
git clone https://github.com/andrey-torlopov/TraceWeave.git
cd TraceWeave
./bootstrap.sh
./traceweave.sh status
```

Bootstrap скачает закреплённые образы, подготовит хранилище и запросит email, имя и пароль с скрытым вводом. Откройте **http://127.0.0.1:8080** и войдите. Создайте исследование, два документа и связь; после подтверждённого сохранения перезагрузите страницу. В разделе «Материалы» выберите «Добавить файлы» для прикрепления оригиналов, включая PDF. В [меню экспорта](exports.md) доступны сырые данные для Obsidian либо единый читаемый отчёт с вложениями.

В меню узла рядом с действиями связи и редактирования выберите **«Удалить узел»**. Это действие также доступно в инспекторе и полном редакторе документа. Подтверждение показывает число затронутых связей; после подтверждённого сохранения узел и все его входящие/исходящие связи исчезнут из графа. Оригиналы вложенных файлов сохраняются. Отмена оставляет граф без изменений; при ошибке используйте предложенный повтор. В архивном исследовании удаление недоступно.

Папка `releases/` содержит выбор 0.1.6. Для точной установки ранее опубликованного выпуска используйте [инструкцию релизов](releases.md). Клонирование текущей документации не меняет версию установленных контейнеров.

```sh
./traceweave.sh stop
./bootstrap.sh
```

Остановка сохраняет данные и выбранный выпуск. Повторный bootstrap показывает установленную версию. Если в каталоге поставки есть более новый совместимый выпуск, он предложит обновление с резервной копией; миграции применяются скриптом только при необходимости. Отказ оставляет прежний выпуск. Сохраните runtime и Docker volumes. При занятом порте новая установка допускает `./bootstrap.sh --port 18080`; её адрес будет http://127.0.0.1:18080.

Если checkout установки отслеживает `main`, проверяйте обновление из его каталога с прежним `TW_RUNTIME_DIR`. Если установка клонировалась из тега выпуска (detached HEAD), сначала выполните [инструкцию для существующей установки](releases.md#существующая-установка): она сохраняет исходный runtime при переходе в новый checkout.

```sh
git pull --ff-only && ./bootstrap.sh
```

Скрипт сравнивает локальные манифесты после `git pull`; скрытых запросов за версиями нет. Подтвердите предложенное обновление, дождитесь завершения и перезагрузите вкладку браузера. Для перехода 0.1.0/0.1.1/0.1.3/0.1.4 → 0.1.6 выбирать манифест вручную не требуется. Обновление применяет схему 9 и обновляет backup tools, сохраняя PostgreSQL и gateway. Откат только образов на более раннюю схему запрещён; для восстановления используется проверенная копия перед обновлением. Подробности — в [руководстве релизов](releases.md).
